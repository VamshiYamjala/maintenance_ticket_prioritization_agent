Live Triage Workflow

End-to-end processing pipeline for incoming shift tickets

Step 1 Ingest & Clean Normalizes text & extracts equipment IDs via regex
Step 2 ML Classify TF-IDF + Logistic Regression suggests category & severity
Step 3 Safety Guard Escalate-only rules check fire, smoke, and trip hazards
Step 4 Runbook & SLA Cosine retrieval for actions, weighted priority & routing
Operational Note:

The system acts as a real-time decision-support layer for control-room analysts. In this prototype, tickets are processed on demand. Results propose ranked causes to check and never autonomously alter physical equipment.

      What is an O&M Runbook?

      Local domain knowledge base mapping equipment faults to safe operational procedures

      data/runbook.json

      An O&M Runbook provides standardized standard operating procedures (SOPs) for field technicians and control-room operators. When a ticket is classified, the triage agent queries the runbook using TF-IDF cosine similarity across fault keywords to attach relevant inspection steps and probable causes.

      Important Safety Distinction: Retrieved probable causes are strictly candidates to check, never confirmed diagnoses. Technicians must perform physical lock-out / tag-out (LOTO) and instrument verification before maintenance.

      Complete 9-Step Agent Workflow

      Deterministic execution trace logged on every triage request

      Step Tool Name Operational Role Deterministic Logic / Model Applied
      1 normalize_and_extract Text Sanitization & Entity Tagging Regex extraction for equipment (WTG-12, Inverter 4) & sites (Block 2)
      2 classify_ticket Category & Severity Proposal TF-IDF (word+char) + Logistic Regression with class-weight balanced
      3 safety_guardrail Hazard Escalation Override Deterministic escalate-only keyword rules with negation check window
      4 lookup_runbook Knowledge Base Retrieval TF-IDF cosine similarity search across local data/runbook.json
      5 check_duplicates Repeat Fault Detection Token Jaccard similarity (>= 0.65) against last 50 in-memory session tickets
      6 compute_priority Transparent Urgency Scoring Deterministic weighted formula calculating exact 0–100 integer score
      7 route_ticket Dispatch Assignment Maps category to O&M team and severity to SLA (1h, 4h, 24h, 72h)
      8 confidence_gate Human-in-the-Loop Safeguard Flags needs_human_review if confidence < 0.45 or margin < 0.12
      9 explanation_layer Analyst Summary Output Deterministic template by default; optional LLM without schema drift

      Priority Scoring Formula

      Fully transparent mathematical weighting without hidden heuristics

      Technology Stack

      Fast, production-viable lightweight architecture

      • Python 3.12: Modern standard runtime
      • FastAPI & Uvicorn: Async REST API with Pydantic validation
      • scikit-learn 1.5: TF-IDF word/char vectorizers and Logistic Regression
      • Pandas & NumPy: Dataset transformations and confusion matrix computation
      • Joblib 1.6: High-performance model serialization (~980 KB)
      • Vanilla HTML5/CSS3/JS: Zero-dependency enterprise UI; instant loading

      Current Prototype Limitations

      Honest assessment of roadmap engineering gaps

      • Synthetic Dataset: 420 synthetic tickets created due to 6-row bundled starter data
      • Single-Label Classification: Compound multi-fault tickets get one primary category
      • English Language: Plant tickets in regional vernacular require multilingual embeddings
      • In-Memory Buffer: Duplicates checked in session memory; requires CMMS SQL persistence
      • No Drift Monitoring: Requires automated retraining loop on production analyst feedback
